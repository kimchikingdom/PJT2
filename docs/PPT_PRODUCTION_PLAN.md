# OWASP Top 10 기반 3티어 웹서비스 PPT 제작 계획

## 1. 발표 목표
- 공공 의료 민원 포털(3-tier) 프로젝트의 구조/기능/취약점 학습 가치를 명확히 전달한다.
- OWASP Top 10:2025 항목별로 "프로젝트 내 재현 포인트"와 "개선 방향"을 1:1로 연결한다.
- 평가 기준(취약점 포함 개수, 분석 완성도)에 맞게 증적 중심으로 구성한다.

## 2. 핵심 메시지
- 이 프로젝트는 Web-WAS-DB 분리 구조에서 보안 취약점이 어떻게 발생하고 확산되는지 실습 가능한 형태로 구현했다.
- 취약점 나열이 목적이 아니라, 각 취약점의 영향/탐지/개선까지 연결 가능한 점이 핵심 산출물이다.
- OWASP A01~A10 전 항목을 커버하며, 운영 관점(로그/모니터링/예외처리)까지 포함한다.

## 3. 슬라이드 구성안 (권장 16장)
1. 표지 (프로젝트명, 팀/발표자, 날짜)
2. 프로젝트 개요 (도메인, 목표, 범위)
3. 3-Tier 아키텍처 (Nginx/Flask/MariaDB, 요청 흐름)
4. 주요 기능 요약 (민원, 게시판, 공지, 관리자, 마이데이터)
5. 보안 실습 설계 원칙 (교육용/폐쇄망/증적 중심)
6. OWASP Top 10 커버리지 요약표
7. A01~A05 요약 (항목별 재현 포인트 + 영향 + 개선)
8. A06~A10 요약 (항목별 재현 포인트 + 영향 + 개선)
9. A01 상세 사례 (접근제어 실패)
10. A05 상세 사례 (인젝션)
11. A07 상세 사례 (인증 실패)
12. A09 상세 사례 (로그/알림 실패)
13. A10 상세 사례 (예외 처리/Fail-Open)
14. 관리자 로그/증적 화면 기반 분석 결과
15. 종합 개선 로드맵 (단기/중기/장기)
16. 결론 및 Q&A

## 4. 장표별 작성 규칙
- 슬라이드 1장당 핵심 문장 1개 + 근거 3개 이내.
- 코드 스니펫은 8~12줄 이하로 제한하고, 전체 코드 대신 취약/개선 포인트만 표시.
- 표/다이어그램 우선: 텍스트 장문 금지.
- 모든 주장에 대해 "프로젝트 파일 경로 또는 라우트"를 하단에 표기.

## 5. 증적 수집 체크리스트
- 아키텍처: `docker-compose.yml`, `web/nginx.conf`
- 기능 증적: 사용자/관리자 주요 화면 캡처
- 취약점 증적: `/security/scenarios`, `/vulnlab/*` 결과 화면
- 로그 증적: `/admin/logs` 이벤트 필터 화면
- 마이데이터 증적: `/profile` 데이터 fetch 및 PDF 다운로드 화면

## 6. 시간 계획 (1회 완성 기준)
- 1단계 (30분): 슬라이드 골격/스토리 확정
- 2단계 (60분): OWASP 항목별 내용/표/근거 채우기
- 3단계 (30분): 스크린샷 반영 및 폰트/레이아웃 정리
- 4단계 (20분): 발표 리허설 및 문장 다듬기
- 5단계 (10분): 최종 검수 (오탈자, 번호, 근거 경로)

## 7. 품질 기준 (100점 목표)
- 완전성: OWASP A01~A10 누락 0개
- 정합성: 발표 내용과 실제 코드/문서 불일치 0건
- 전달력: 슬라이드당 핵심 메시지 명확성 (한 문장 요약 가능)
- 실무성: 각 취약점마다 개선 액션이 구체적으로 제시됨
